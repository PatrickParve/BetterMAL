**Follow-up fix (post-verification):** user reported Dragon Ball Z's More overlay still showed many relations as "Unknown" after this shipped. Root cause: anime already fully synced *before* the `MediaType` column existed (e.g. DBZ, `LastSyncedAt` = 2026-08-08) have `Genres` populated, so `NeedsFullDetailFetch`'s existing predicate never re-triggers a fetch — their `AnimeRelatedAnime` rows keep `MediaType = null` forever, and the cache-lookup fallback only resolves relations we've *separately* cached (most of DBZ's 35 weren't). Fixed by adding a second migration-cutoff clause to `AnimeDetailService.NeedsFullDetailFetch` (`RelatedAnimeMediaTypeMigrationCutoff = 2026-08-09`, mirroring the existing `RelatedAnimeMigrationCutoff` pattern): an anime with relations but any relation missing `MediaType`, last synced before this cutoff, gets one more full-detail refetch — which MAL populates for every relation regardless of whether we've cached that related anime ourselves. Verified: DBZ (813) went from 0/35 to 35/35 relations with `MediaType` after one re-visit; the More overlay showed 0 "Unknown" out of 33 listed relations, with only the one expected `GET /api/anime/813` (no extra backfill calls).
