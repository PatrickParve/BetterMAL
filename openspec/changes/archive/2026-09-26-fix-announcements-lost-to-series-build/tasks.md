## 1. Record the verdict on the discovery

- [x] 1.1 `Models/RelationDiscovery.cs`: add `public bool? RelatedAnimeHadFullDetail { get; set; }`. Document it in the class summary alongside `ProcessedAt` (design D1, D2): it is whether `RelatedAnimeId` had ever had a full-detail fetch at the moment this row was written; `false` includes "had no cached row at all"; `null` means the row predates this column and the resolver falls back to reading the anime's current `LastSyncedAt`. Say why it is stored rather than derived later — the series rebuild this same detection queues fetches the far end within seconds, and every later reading of `LastSyncedAt` reports that fetch instead of the past.
- [x] 1.2 `Services/Updates/AnimeMetadataChangeDetector.cs`: make `RecordDiscoveries` `async Task`, taking the same arguments, and have it read the far ends' committed state first (design D3):
  - one query over the distinct `RelatedAnimeId`s of `newEdges`: `db.AnimeMetadata.AsNoTracking().Where(a => ids.Contains(a.Id)).Select(a => new { a.Id, a.LastSyncedAt })`, materialised to a dictionary;
  - each row's `RelatedAnimeHadFullDetail` is `dict.TryGetValue(id, out var syncedAt) && syncedAt != default`;
  - comment why the query is a projection and not a tracked entity read: `RefreshStaleBatchAsync` refreshes up to twenty anime against one context and saves once at the end, so a tracked read could return a far end whose `ApplyTo` has already stamped `LastSyncedAt` in memory and report full detail for an anime the database has never seen fetched.
- [x] 1.3 `AnimeMetadataChangeDetector.RecordAsync`: `await` the new `RecordDiscoveries`, and extend the comment on the `seriesBuildTrigger.Enqueue` call (design D4) to record that its position after the discovery writes is now load-bearing — the rebuild it queues is what fetches the new far end, and the verdict above must be read before that can happen.
- [x] 1.4 Add the EF migration for the new column: `dotnet ef migrations add AddRelationDiscoveryRelatedAnimeHadFullDetail` from `backend/AnimeTracker.Api`. It must be a nullable `boolean` with no default and no backfill (design D2). Check the generated `Up`/`Down` and the model snapshot; no index and no `DbContext` configuration change is needed.
