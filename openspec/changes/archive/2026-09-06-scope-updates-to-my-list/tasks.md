## 1. Extract the eligibility test into one service (design D2)

- [x] 1.1 Add `Services/Updates/IAnimeUpdateRelevance.cs` with `Task<bool> IsRelevantAsync(int animeId, CancellationToken ct = default)` and `Task<ResolvedRelationEdge?> FindAffiliateAsync(AnimeMetadata anime, CancellationToken ct = default)`. Document on the interface that this is the single implementation of the spec's eligibility rule, read by both the recording gate ("Nothing is recorded for an anime outside my list and its direct relations") and the display filter ("Updates are shown for my own entries and for their franchises"), and that two copies would drift silently.
- [x] 1.2 Implement `Services/Updates/AnimeUpdateRelevance.cs` taking `AnimeTrackerDbContext` and `IRelationResolver`. Move the body of `AnimeUpdateService.TryDeriveAffiliateReasonAsync` into `FindAffiliateAsync` unchanged — `GetEdgesAsync`, the `Confidence != Contradicted` filter, the far-end non-Dropped lookup, and the `RelationPrecedence`/title tie-break that picks the winner — returning the winning `ResolvedRelationEdge` instead of a rendered string.
- [x] 1.3 Implement `IsRelevantAsync(animeId)` in the three cheapest-first steps of design D3: (a) `UserAnimeEntries.AnyAsync(e => e.AnimeId == animeId && e.Status != WatchStatus.Dropped)`; (b) a single both-directions existence query over `AnimeRelatedAnime` joined to non-Dropped `UserAnimeEntries`, returning `false` when it finds nothing; (c) only then load the anime `AsNoTracking().Include(a => a.RelatedAnime)` and call `FindAffiliateAsync`. Comment why step (b) exists — it is the common irrelevant case (every stranger a season browse writes) and must not cost a resolver call.
- [x] 1.4 Comment why `IsRelevantAsync` takes an id and loads its own state rather than trusting the caller's entity: `GetEdgesAsync` needs `RelatedAnime` loaded, and the lean listing writers and `EpisodeScheduleRefreshService` neither `Include` it nor touch it, so an unloaded collection would read as "no outgoing edges" and judge a linked anime irrelevant.
- [x] 1.5 Comment the `AsNoTracking` choice in step (c): it reads committed state, matching the read side exactly, and the only edges it cannot see are ones written in the same unsaved unit of work — an anime's own fetch, whose field updates the first-full-fetch rule already silences.
- [x] 1.6 Rewrite `AnimeUpdateService.TryDeriveAffiliateReasonAsync` as a thin wrapper over `FindAffiliateAsync` that humanizes the winning edge (`RelationInverse.Invert` + `HumanizeRelation`), leaving `RelationPrecedence`, `HumanizeRelation`, `OwnStatusReason` and `ResolveReasonAsync`'s own-entry short-circuit where they are — display concerns, not eligibility.
- [x] 1.7 Register `IAnimeUpdateRelevance` as scoped in `Program.cs` beside the other `Services/Updates` registrations.

## 4. Announcements only for anime never seen before (design D5)

- [x] 4.5 Extend the class's existing airing-gate comment with the never-fully-fetched rule, stating what an announcement now means: something the system had never seen appeared in the relations of an anime on the user's list.
